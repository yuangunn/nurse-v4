## 1. 아키텍처 결정 (Accepted)

### 1-1. 데스크톱 패키징 = Electron + @electron/packager (NOT electron-builder)
- **결정**: `@electron/packager` v19 + 수동 Inno Setup(ISCC) 조합
- **이유**: `electron-builder` 26.x가 Windows에서 `winCodeSign` 심볼릭 링크 생성 실패. 개발자 모드 없는 환경에선 빌드 자체가 깨짐.
- **대안 폐기**: `electron-builder` `"nsis"` 타겟 — 빌드 시 symlink 권한 에러.
- **파일**: `electron/package.json`, `installer/setup.iss`, `build.bat`

### 1-2. Python 서버 ↔ Electron IPC = stdout "PORT:<n>"
- **결정**: `main.py`가 `sys.stdout.write(f"PORT:{port}\n")`로 Electron에 포트 전달.
- **이유**: 포트 충돌 가능. Python이 `find_free_port()`로 동적 할당하고 Electron `main.js`가 stdout 라인 파싱.
- **주의**: `--windowed`(console=False)에서 `sys.stdout is None`. `_ensure_stdio()`로 devnull 대체 + try/except로 write 감쌈.
- **파일**: `main.py:_ensure_stdio()`, `electron/main.js`

### 1-3. 프로필 데이터 암호화 = Fernet (PBKDF2 100k iterations)
- **결정**: `cryptography` 라이브러리, 프로필별 DB 파일 + 마스터 비밀번호로 Fernet 키 파생.
- **파일**: `server/profiles.py`
- **게스트 모드**: `_guest_temp.db` — 종료 시 삭제.

### 1-4. MIP 솔버 = `pulp.HiGHS` (Python 바인딩), NOT `pulp.HiGHS_CMD`
- **이유**: `HiGHS_CMD`는 highs.exe 경로 문제로 PyInstaller 빌드에서 동작 불가.
- **의존성**: `highspy` 패키지 (PyInstaller `--hidden-import=highspy` 필수).

### 1-5. 시니어리티 = `nurses` 리스트 순서 (0번이 가장 선임)
- **결정**: 별도 `seniority` 필드 없이 순서로 표현.
- **Charge 규칙**: 더 선임이 같은 듀티에서 일반 근무(D/E/N)로 배정되면, 후임은 그 듀티의 Charge(DC/EC/NC) 불가.

### 1-6. D/E/N 라벨 유지 (낮/저녁/야간으로 바꾸지 말 것)
- **사용자 명시 지시**: "누가 D/E/N을 낮/저녁/야간으로 바꾸래?"
- 근무 코드는 원본 영문 유지.

### 1-7. 사이드바 로고 = `18px !important` 고정
- **사용자 명시 지시**: "NurseScheduler v4 18px로 고정해줘"
- `fontSize` 설정이 커져도 로고는 변하지 않음.
- **파일**: `frontend/css/app.css` `.sidebar-logo { font-size: 18px !important }`

### 1-8. 일별 인원 제약 = `==` (정확히 일치)
- 초과 배정 불가. `_c_daily_requirements()` 에서 `==` 사용.

### 1-9. 소프트 제약 preBonus = 차등 (2026-08-20 정정)
- `preBonusLeave: 5000` > `preBonusOff: 3000`(OF·P1) > `preBonusWork: 500` > `preBonusRest: 300`(주휴,
  `allow_juhu_relax` 시에만 변수). 완화 시 **근무가 먼저**, 쉬는 날·휴가는 개인의 시간이라 늦게.
- 2단계 사전순: 1단계 '유지 보너스'만 gap 0으로 최대화(뒤집는 셀 수 확정) → 2단계 그 수준을
  하드로 고정하고 배점 최적화. 1단계 미증명 시 dom 가중 단일 솔브 폴백.
- 구버전 문서("쉬는 날 300, 가장 유연")는 코드와 달랐다 — `preBonusOff`는 코드에 getattr
  기본값으로만 있었고 모델·UI·매뉴얼에 없었다(M6 조사 F4). 2026-08-20 모델 필드·슬라이더 추가.
- **보호 채널은 잠금(🔒)뿐** — 메모는 기록용 (사용자 결정, 제1원칙 9).
- **파일**: `server/scheduler.py:_solve_with_relaxed_pre()`, `scheduler_cpsat.py` 완화, `models.py Rules`

### 1-12. CSS 변수는 `--bg-card`, NOT `--card` (2026-04-19 확정)
- **결정**: 카드 배경은 항상 `var(--bg-card)` 사용.
- **이유**: `--card`는 정의되지 않았음. 과거 코드가 `var(--card, #fff)` 쓰면 fallback으로 항상 흰색이 돼서 다크모드가 깨짐 (프로필창·온보딩 모달 안 보임 버그 원인).

### 1-13. 임산부 모성보호 = 변수 게이팅 + P1 주1회 하드 (2026-06-02 확정)
- **결정**: 임산부 기능을 "새 제약 메서드 최소화 + 변수 도메인 게이팅" 방식으로 구현.
  - 새 근무 `P1`(임부휴무, period=rest, auto_assign=1). `_DEFAULT_SHIFTS`+DB seed+마이그레이션(INSERT OR IGNORE) 모두 추가.
  - **야간 제외·생 면제·P1 구간 제한은 전부 변수 게이팅**(`_preg_forbids`로 해당 셀 변수=0) — 별도 제약식 불필요. 야간/생 사전입력은 `_preg_effective_pre`로 드롭(사전입력 N 강제→infeasible 회피).
  - **유일한 양(positive) 제약 = P1 주1회**(`_c_pregnancy_p1_weekly`/`_cs_pregnancy_p1_weekly`): 구간 완전 포함 주 `==1`, 부분 주 `≤1` (weeklyOff 패턴).
- **이유**: 게이팅은 HiGHS 2곳(solve+relaxed)·CP-SAT 2곳(build_vars+relaxed)·conflict_analyzer(build_vars_mcs)에 헬퍼 호출 1줄씩만 추가하면 끝 → 5엔진경로 패리티가 단순·견고. P1을 SOLVER_SHIFTS에 두되 게이팅으로 비임산부·구간밖은 0.
- **야간 제외 구간 = `[early.start, late.end]` 전체**(중기 포함). 2구간 입력만으로 "임신~출산" 도출(별도 임신 전체구간 칸 없음).
- **임산부 달엔 `is_night_shift` 자동 해제**(`__init__`): 야간전담 14일 의무와 야간 면제 충돌 방지.
- **P1 보호등급 = OFF급**(`timeoff_class`→'off', `_OFF_CODES`={OF,P1}): 완화/MCS에서 근무보다 강하게 보호.
- **파일**: `models.py`(is_pregnant,pregnancy)·`database.py`(2컬럼+P1 seed/마이그)·`scheduler_base.py`(헬퍼 5종+게이팅+분류)·`scheduler_highs_constraints.py`·`scheduler.py`(solve/relaxed 게이팅)·`scheduler_cpsat.py`·`conflict_analyzer.py`·`frontend`(모달 카드+🤰배지). 테스트 `tests/test_pregnancy.py`(양엔진 10건).

### 1-14. 완전 확정 표 폴백 — 완성 번표는 '주어진 사실' (2026-08-19 확정)
- **결정**: 당월 재적 셀이 사전입력으로 **빈칸 없이** 채워져 있으면, 솔버가
  infeasible/타임아웃이어도 실패를 반환하지 않고 **표를 그대로 근무표로 확정**한다
  (`pinned_confirmed`, 점수 계산 포함). 앱 규칙과 다른 부분(일별 인원·전환·주별 OF·
  V/야간 한도·연속·야간전담 일수)은 `pinned_notes` **참고 목록**으로만 알린다.
- **이유**: 이미 만들어진(지나간) 번표는 검증 대상이 아니라 주어진 사실 — 인원 수치를
  대며 거부하면 사용자는 원인을 알 수 없다. 규칙은 솔버의 '자유 배정'을 제한하는
  것이지 사용자가 직접 확정한 표를 거부하는 장치가 아니다.
- **우선순위**: 완화(allow_pre_relax)를 명시로 켰으면 완화가 먼저(표를 고쳐서라도
  규칙을 맞추길 원한 것), 실패 시 폴백. 폴백은 진단보다 먼저.
- **파일**: `scheduler_base.py`(`_fully_pinned`/`_confirm_pinned_result`/`_pinned_rule_notes`),
  `scheduler.py`·`scheduler_cpsat.py` 실패 분기 4곳. 테스트 `tests/test_pinned_confirm.py`.
- **현황**: 1-15 사실-클램프 도입 후 완전 확정 표는 대부분 솔버가 **직접 성공**하므로
  이 폴백은 안전망(예: 타임아웃)으로만 남는다.

### 1-15. 사실-클램프 — 부분 확정 일반화 (2026-08-19 확정)
- **결정**: 1-14를 **부분 확정**까지 일반화. "2주차까지만 꽉 채우고 바꾸고 싶은 부분만
  비워서 생성"도 확정 부분은 검증하지 않는다 (사용자: "일단위로 근무표가 모두 차있다면
  그 일에만 확정하는 게 맞지 않을까"). 구현 의미론 2가지:
  - **스킵**: 제약에 걸리는 셀이 **전부 확정**이면 그 제약을 걸지 않는다 — 일 전체
    확정(일별 인원·charge·시니어리티, 변수도 리터럴화해 승격 플렉스 제거), 인접
    쌍/3셀 확정(금지 전환·NOD), 윈도우 확정(연속 근무/야간), 주 전체 확정(주 OF·P1),
    확정 휴식일(restAfterNight의 rest_d), 확정 셀 eligibility.
  - **클램프**: 확정+자유 혼합 카운트 제약은 상한(RHS)을 `max(규칙 한도, 확정분)`으로
    올린다 — 일별 인원, 주 OF/P1 bound, 월 V/야간/생/홀짝월, 야간전담 5일 윈도우·월간
    목표. 효과: 기존 확정(예: OF 2회)은 수용하되 **자유 셀이 위반을 더 늘리는 건 금지**.
- **비활성 조건**: `allow_pre_relax=True`면 `_pin={}`로 클램프 전체 OFF — 완화를 명시로
  켠 사용자는 "표를 고쳐서라도 규칙을 맞춰라"는 뜻 (1-14 우선순위와 동일).
- **안내**: strict 성공 결과에 `_attach_pin_notes()`가 `pinned_notes`(확정 사실 vs 앱
  규칙 차이: 인원/전환/OF/V/연속/restAfterNight/NOD/야간전담)를 덧붙인다. 확정 표가
  참이므로 성공해도 사용자는 차이를 안다.
- **진단과의 관계**: 진단 13단계는 `_c_*` 재사용이라 클램프가 자동 일관 — 확정만으로
  완결된 위반은 진단 대상에서도 빠진다(그건 이제 실패 원인이 아니므로 올바름).
  완화 경로에서 진단이 돌 땐 `_pin`이 비어 있어 종전대로 사전입력 직접 위반을 짚는다.
  `conflict_analyzer`의 `analyze()`/`suggest_correction()`은 **의도적으로 클램프
  미적용** — "이 표가 앱 규칙과 어디서 충돌하나"를 설명하는 도구라 사실 수용이
  아니라 전수 검사가 맞다. 단 **`check_feasibility()`(신호등 프로브)는 클램프 적용**
  (2026-08-19 후속 수정): 신호등은 '생성이 되는가'의 판정자라 엔진 의미론과 일치해야
  한다 — 미적용 시 엔진이 수용하는 입력(확정 OF 2회 주 등)에 거짓 빨강.
  주의: 프로브 2단계·CP-SAT 실패 시 정밀 분석의 원인 **라벨**은 여전히 무클램프
  게이티드 모델에서 나오므로, 클램프가 수용하는 항목이 라벨로 나올 수 있다(참고용).
- **파일**: `scheduler_base.py`(`_build_pin_index`/`_day_all_pinned`/`_pin_day_period_count`
  /`_pin_nurse_count`/`_attach_pin_notes`), `scheduler_highs_constraints.py` 12곳,
  `scheduler_cpsat.py` 미러 12곳. 테스트 `tests/test_partial_pin_facts.py`(신규),

### 1-16. 오프특근 — 휴무 공급이 모자랄 때의 마지막 수단 (2026-08-20, 3차 수정이 최종)
- **결정(현행, v4.10.0)**: 주 1회 OF는 **최대한 지키는 의무**다. 모델은

      Σ_{완전한 주} OF + s = bound        (s ∈ {0,1} = 오프특근 슬랙)
      목적함수 -= 1_000_000 × s

  상한(주 2회 금지)은 하드로 남고, 1회 의무는 **어떤 배점 조합보다 큰 페널티**로
  지킨다 → s는 "그러지 않으면 근무표가 성립하지 않을 때"만 켜진다. 켜진 주는
  결과 `off_teukgeun`(간호사·주차·기간)으로 보고하고 메시지에도 붙는다.
- **왜 이 모양인가 (사용자 재설명 원문 요지)**: "오프특근은 어쩔 수 없으면
  발생하는 거야. **경가·조가 등 휴무가 갑자기 많아진 경우에는 다른 근무자들이
  오프를 줄여가면서 근무를 뛰어야 한다**는 거고, 그에 대한 **최소한의 휴무 보장이
  주휴**인 거야." → 트리거는 **휴무 공급 부족**이지 공휴일이 아니다. 조건부 면제가
  아니라 '지킬 수 있으면 지키고, 못 지키면 반납하되 기록에 남긴다'가 맞는 모델.
- **두 번의 오답 (반복 금지)**:
  1. v4.8.0 — "당월 공휴일이 낀 완전한 주는 누구나 OF ≤1". 트리거를 공휴일로 오인.
  2. v4.9.0 — "그 주 공휴일에 법휴를 받았거나 근무한 사람만 면제". 여전히 공휴일
     기반이고, 게다가 연휴 달이 법휴 7~10명에도 안 풀렸다(CP-SAT UNKNOWN).
  둘 다 **제1원칙 3의 예시(공휴일이 몰린 주)를 조건으로 착각**한 것이다. 예시는
  "그런 주에 흔히 생긴다"는 뜻이지 "그런 주에만 허용된다"가 아니다.
- **부수 효과 (의도한 것)**: 주휴 슬랙이 모자란 구성은 이제 infeasible이 아니라
  '오프특근 n건'으로 생성된다. 진단 Phase 5의 '주간 휴무 공급 부족' 경로는 사실상
  도달하지 않으며, Phase 8 주간 산식도 의무 휴무를 주휴 1로만 센다.
  최소 보장(주휴)은 사전입력이라 엔진이 건드리지 않는다.
- **파일**: `scheduler_base._OFF_TEUKGEUN_PENALTY`/`_off_teukgeun_report`/
  `_attach_reports`, `_c_weekly_off`·`_cs_weekly_off`(슬랙), 양 엔진 목적함수,
  `conflict_analyzer._g_weekly_off`(상한만 게이팅), 진단 Phase 8,
  프론트 `solver.js`/`app.js`/`index.html`(⚠ 오프특근 패널).

### 2-21. 목록(x-for)을 품은 블록에 x-if 를 쓰면 내려가는 찰나 안쪽 x-for 가 한 번 더 돈다 (2026-09-06)

### 2-22. 'HTML 안 기본 설정'은 안 된다 — 데이터 파일이 유일한 저장소, HTML 은 병동 중립 (2026-09-17)

### 2-42. 102 CRN 은 방이 고정이 아니다 — 차지는 사람, 앉는 자리는 연속성 (2026-10-01)

  2026-09-20 에 '102 차지는 자리를 옮기지 않고 이름 뒤에 /CRN' 으로 바꿨지만, 코어는 여전히 차지를 **'차지' 자리(= 102 종이의 A)** 에 앉혔다.
  그래서 ① CRN 이 바뀌는 날(선임이 쉬는 날) 새 CRN 이 A 로 끌려가고 A 사람이 밀려 연쇄로 자리가 바뀌었고 ② 실제처럼 CRN 을 B 로 손으로 옮기면
  /CRN 표시가 A 에 앉은 다른 사람에게 붙었고(표시가 자리를 따랐다) ③ 다음 날 CRN 이 다시 A 로 돌아가 둘이 또 뒤바뀌었다.

  그 목록 중 한 자리에 앉는다. 자리는 허락된 빈 자리마다 '차지 자신의 연속성 + 나머지의 최대 매칭'을 매겨 가장 큰 곳(동점이면 앞 자리) — 어제 B 를 본 CRN 은 B,
  어제 D 를 본 사람이 CRN 이 되면 D(허락 목록 밖 자리를 본 사람이면 남들이 가장 덜 밀리는 자리로). 그 뒤 매칭(a)·라벨 폴백(b)·잔여는 차지를 뺀 나머지로 그대로 돈다.

  같은 날 사용자 "당연히 D방도 볼수있지 … /CRN은 사람에 붙는거야" — CRN 은 사람이고 어느 방이든 본다. 종이 줄을 넘는 자리(대체 줄)만 뺀다

### 2-46. 그룹원끼리 인계 피하기 — 주지 않을 방 다음, 이어 보기보다 먼저 (2026-10-09)

  크기는 병상수 합(이어 보기 겹침과 같은 잣대). 같은 그룹 = 서로 다른 두 사람의 그룹이 하나라도 겹침. 그저께 N·전날 D 처럼 바로 앞이 아닌 근무는 세지 않는다.
- **순서**: [주지 않을 방 > 같은 그룹 인계 > 원칙 1~3 > 헬퍼는 후임 > 원칙 4 튕김 > 누가 잇는지 > 덜 옮기기] — 마지막 다듬기(`polish`)와 CRN 자리 고르기 둘 다.
  '최대한 피하게'라 이어 보기보다 먼저 둔다. 이어 보기 다음으로 두면 방을 이어 볼 수 있는 날마다 인계가 그대로 남는다(D → E 는 이어 보기가 앞 근무 사람의 방을 주려고 한다).
  대가: 자리가 조금 더 자주 바뀐다(두 달 예시 101: 옮김 136 → 143, 102: 29 → 45). 헬퍼는 후임보다 이어 보기가 먼저인 것과 같은 이유로 6명 이상인 날
  선임 신규가 헬퍼가 될 수 있다.
- **바꾸지 않는 것**: 누가 차지인지(그룹과 상관없이 시니어리티·DC/EC/NC) · 손으로 정한 자리 · 고정 차지 자리 · 방 정보(`roomsFor`)가 없으면 아무 일도 안 한다.
  그래서 피할 수 없는 인계가 남는다 — 2인 N 의 E → N(차지 아닌 자리가 하나), 차지 → 차지(고정 차지 자리), 손으로 정한 자리. 코어가 `byDay[날][근무].handover` 로 알리고
  확인 카드에 노란 안내.
- **확인 카드는 그룹마다 한 줄**: 처음엔 짝마다 한 줄 + [배정 원칙 열기] 단추였는데, 피할 수 없는 E → N 이 주마다 여러 줄 쌓였고 단추는 고치는 길이 아니었다(그룹을 끄는 것뿐).
  지금은 `같은 그룹(이름) 인계 n건 — 날 근무 준 사람 → 근무 받은 사람 (방) · …`, 넷 넘으면 셋만 보이고 [n건 더 보기], 까닭은 끝에 한 번. 단추는 차지 자리 탓일 때 방 구성만.
- **화면**: 간호사 관리 [＋ 그룹 만들기] · 그룹 띠(이름·병동 그룹원 수·인계 피하기 상태·✎ ✕) · 표의 그룹 칸 칩. 배정 원칙 맨 아래 그룹마다 스위치(새 그룹은 켠 채 시작,
  병동 그룹원 둘 이상일 때만 쓰인다). 다른 소속(SU)은 병동 자리에 앉지 않아 세지 않지만, 그룹원이었으면 칩이 남아 뺄 수 있다. 그룹이 있으면 좁은 창(1280·1366)에서
  간호사 표가 옆으로 밀려 남는 폭에 맞춰 그룹 칸(칩 하나 폭까지)·가능 근무·이름 칸 순으로 줄인다.
- **검사**: 원칙 검사에 정답 쪽 정의를 요구 사항에서 바로 옮겼다(E13 정답과 같은 비용 · E14 차지 불변 · E15 넘겨받을 게 없으면 그룹 없는 것과 같음 · E16 알린 인계 =
  정답이 센 인계 · S0). 고장 넣어 보기(순서 뒤집기·병상 두 번 세기 등) 모두 잡힘 — `docs/verification.md`. 실시간 수정 101·102 에 그룹을 넣어 E8(엔진 보고 = 근무표로 센 인계)·
  V1(카드 = 엔진 보고). 원칙 검사가 약 20초 → 40초.
- **교차 검토 후속 (같은 날)**: 엔진 오류는 없었다(따로 짠 전수 대조 0건, 고장 26개 모두 잡힘). 고친 것 —
  ① 확인 카드의 까닭을 그 날 실제 까닭으로: 받은 사람 자리를 손으로 정함 · 차지 자리 방(고정 차지, 차지가 바뀐 날만) · 다른 사람 손 자리 · 주지 않을 방 ·
  그 밖은 '뒤 근무 자리만으로는 피할 수 없던 날 — 넘겨준 사람(앞 근무)의 자리를 바꾸면 피할 수 있을 때가 있다'. 엔진은 앞 근무를 옮기지 않으므로 카드가 그 길을 알려 준다.
  ② 좁은 창 맞춤이 부모 여백을 빼지 않아 여전히 밀렸고 주지 않을 방 칸을 눌렀다 — 여백을 빼고 주지 않을 방 칸은 최소 140px.
  ③ 이름을 바꾸면 다른 소속(SU) 표시가 옛 이름에 남아 새 이름이 병동 자리로 들어왔다 — 함께 옮기고, 지우면 뗀다. 소속 켜고 끄기도 Ctrl+Z.
  ④ 백업 불러오기·다른 파일 열기 뒤 Ctrl+Z 가 앞 파일의 상태로 돌아갔다 — 되돌리기 기록을 비운다. ⑤ 옛 파일의 그룹(`normGroups`)은 이름·그룹원 없는 항목을 버리고
  이름을 다듬어 겹치면 번호를 붙이며, 'false'·0 을 꺼짐으로 읽는다. ⑥ 이름이 든 onclick 은 `escA(jsq())` 로 — 따옴표가 든 이름에서 단추가 깨졌다.
  검사 보강: 코어에 'CRN 자리 고르기도 주지 않을 방 > 인계' 시나리오(순서를 뒤집으면 실패), 실시간 수정 E8 은 앱 함수 대신 그룹 목록에서 따로 짠 그룹으로 견주고,
  V1 은 1920 에서 카드가 옆 열이 아니면 실패, 수정이 건드리지 않는 그룹을 하나 두어 켠 그룹이 늘 남게.

### 2-47. 그룹원·인계 피하기는 고친 날부터 — 지난 배정은 그대로 (2026-10-09)
- **결정 카드 답 (원근)**: '그룹원을 넣고 빼면 어느 날짜 배정부터 바뀌게 할까요?' → **고친 날부터**. 같은 날 다른 카드 '앞 근무 사람 자리도 옮길까요?' → **뒤 근무만**(엔진은 그대로).
- **기록**: `store.groupLog=[{from:'YYYY-MM-DD', groups}]` — 첫 기록은 from '' (처음부터), 마지막 기록 날부터는 `store.groups`(지금 상태, 화면이 보이는 것). 비었으면 `store.groups` 가 모든 날.
  그룹원 넣고 빼기·스위치·그룹 지우기 뒤 `noteGroups(prev)` 가 오늘(이 컴퓨터 날짜, `editDay`)부터의 기록을 지금 상태로 — 같은 날 여러 번 고치면 하나, 앞 기록과 같아지면 접고,
  처음 하나만 남으면 기록을 비운다. 배정에 상관없는 변화(이름, 켜졌지만 그룹원이 하나뿐인 그룹)는 기록하지 않는다(`grpShape`).
- **엔진**: `handoverGroups` 를 함수 `(dk)=>{id:[그룹]}` 로도 받는다 — 인계는 **받는 근무의 날** 그룹으로 잰다(N→D 면 다음 날 아침). 앱은 기록이 있을 때만 함수로 넘기고(기록마다 한 번 계산),
  없으면 예전처럼 객체. 하루의 배정은 그 날까지의 근무표·그룹만 보므로 고친 날 앞 배정은 바뀌지 않는다.
- **따라가는 것**: 간호사 이름 바꾸기·지우기는 지난 기록의 그룹원도 바꾼다. Ctrl+Z·저장·백업에 기록이 든다. 파일을 열 때 `fixGroupLog` 가 모양을 맞추고, 기록을 모르는 판에서
  그룹을 고친 파일(마지막 기록 ≠ 지금)은 그 차이를 오늘부터로 친다.
- **검사**: 코어 무작위 대조의 셋 중 하나는 날마다 그룹이 바뀌고(받는 날 그룹으로 고치면 실패하는 고장 둘 확인), 로직 37절 '고친 날부터' 12건, 실시간 수정은 그룹 수정을 고른 날을 오늘로 하고
  E8 은 그 날 그룹으로 견주며 O11 '그 전 날 배정 그대로'(기록을 무시하는 고장을 넣으면 101·102 에서 잡힘), e2e 는 기록이 처음·오늘.

### 2-48. 그룹의 가능 근무·주지 않을 방 — 그룹원 각자 설정 위에 더한다 (2026-10-09)
- **요청 (원근)**: "그룹별 가능근무 수정, 그룹별 배정하지 않을 방을 지정하는 기능도". 결정 카드 '그룹 규칙'(그룹 자체에 제한을 단다) vs '한꺼번에 고치기'(그룹원 각자 칸을 일괄 수정) → **그룹 규칙**.
- **모양**: `store.groups[*].caps?`(그룹원이 할 수 있는 근무 — 없으면 제한 없음) · `bans?`(그룹원 모두에게 주지 않을 방, 호실·병상 토큰). `grpRestrict` 가 늘 caps → bans 순으로 달고 없으면 칸을 두지 않는다(옛 파일 모양 그대로).
- **합치는 규칙**: 가능 근무 = 개인 ∩ 그 날 든 그룹마다의 가능 근무 — **그룹은 끄기만 하고 켜 주지는 못한다**. 주지 않을 방 = 개인 ∪ 그룹들. 그룹에서 빼면 바로 풀리고 개인 설정은 그대로(`capsAt`·`bansAt`).
  `capsOf` 는 개인 설정 그대로 — 간호사 관리의 칩이 고치는 것. 그룹에서 꺼 둔 근무는 칩을 점선으로, 개인 칩을 눌러도 켜지지 않고 알린다.
- **고친 날부터**: 2-47 기록(`groupLog`)을 그대로 쓴다 — `grpShape` 가 제한만 있는 그룹·그룹원 하나인 그룹도 배정에 쓰이는 모양으로 보게 했다(빠뜨리면 그런 그룹의 제한이 지난 배정까지 바꾼다).
  그래서 차지 자격이 날마다 달라질 수 있어 코어 `chargeCapable` 을 `(P, 날짜)` 함수로도 받는다(그룹 모양이 같은 날끼리 한 번만 센다).
- **따라가는 것**: 호실 이름 바꾸기·지우기·병동 바꾸기가 지금 그룹과 기록 속 그룹의 방도 옮긴다(호실 이름이 바뀐 것이지 그룹을 고친 것이 아니라 고친 날로 치지 않는다).
  확인 카드의 '가능 근무가 아닙니다'·'주지 않을 방' 줄은 그룹 탓이면 그룹 이름을 함께. 개인 가능 근무·주지 않을 방 고치기도 이참에 Ctrl+Z 로 되돌린다.
- **다른 소속(SU)** 은 병동 자리에 앉지 않아 그룹 제한을 쓰지 않는다(인계 피하기와 같다).
- **검사**: 로직 38절, 실시간 수정 E5(날마다 그룹 가능 근무)·E9(엔진에 넘긴 주지 않을 방 = 개인 ∪ 그 날 그룹)·그룹 표 조작.

### 2-49. 예시로 둘러보기 — 병동별 예시 데이터는 메모리에서만 연다 (2026-10-09)
- **요청 (원근)**: "병동별 예시 js 파일을 추가하고 근무표도 임의로 채워서 한번 사용할수 있게 — 처음 쓰는 사람한테 모든 걸 알려 주는 덴 시연만 한 게 없다".
- **만드는 함수 하나**: `makeExample(병동,{start})` — 병동 번호가 씨앗(mulberry32)이라 같은 병동이면 늘 같은 사람·같은 순서, 날짜만 '지난주 ~ 4주 뒤'(5주)로 따라간다.
  병실·병상·서식·방 구성은 그 병동 것(`wardRooms`·`FORMS`·`DEFAULT_ROOMS`) — **HTML 에 병동 값을 새로 넣지 않는다**(결정 2-22). 서식 모양마다 근무 순환(`EX_PLAN`)을 두고
  차지 가능한 선임의 출발점을 고르게 벌려 날마다 D·E·N 에 차지 가능자가 있게 했다. 종이 칸을 넘지 않는다(101·122 D5 중1 E5 N3, 122 는 월·수·금 대체간호사로 D6, 102 D4 E4 N3, 82 병동 D2 중1 E2 N1 + SU 4명).

  개인 주지 않을 방 하나(82 밖), 교육·행사 세 가지(매주 목요일·하루·기간), 당직표(GS 늘 같은 번호 · OS · 진료지원 내선). 5주 모두 확인 카드에 '확인 필요'가 없다.

  (`_writeStore`·`touch`·`beforeunload`·옛 키 옮기기 모두 예시면 건너뛴다). 우리 병동 파일이 열려 있었으면 고친 것을 먼저 저장하고 상태를 통째로 기억(`demoPrev`) — [예시 끝내기]면
  그 파일로 그대로 돌아온다. 파일이 없었으면 시작 화면. 예시에서 진짜 파일을 열거나 만들면(`useHandle`) 예시를 버린다(`quitDemo`).
- **예시 파일**: `standalone/예시/<병동>병동 예시.js` 14개 — `scripts/make-assign-examples.mjs` 가 같은 `makeExample` 로 만든다(날짜는 2026-10-04 주 고정, 그 안이면 이번 주부터 보인다).
  파일에 `example` 표시가 있어 **어느 길로 열어도 예시로 연다** — [데이터 파일 열기](권한을 묻기 전에 내용부터 본다 — 허락 창이 뜨지 않는다)·끌어 놓기·백업 불러오기·옆에 둔 파일.
  예시 파일에 고친 것이 쌓이면 다음 사람이 엉뚱한 예시를 본다. CI `--check` 가 지금 HTML 로 다시 만든 것과 같은지 + 14개 모두 5주 '확인 필요' 0 · 엑셀 · 인쇄 · 하루 어싸인표를 본다.

- **HTML 안에서 예시 파일 받기 (2026-10-10, 원근 "인트라넷에서 시연용 파일을 html 안에서 내려받을 방법 — 하드코딩해도 용량 별로 안 차지할 텐데")**: 인트라넷 병동에는 리포의 `예시/` 폴더가 없다. 파일을 HTML 에 넣어 두지 않고 `downloadExample(병동)` 이 **`makeExample` 로 그 자리에서 만들어** 내려준다 — HTML 크기 그대로(14개를 박으면 약 230KB), 날짜는 받는 날 기준 '지난주 ~ 4주 뒤'(박은 파일은 날짜가 굳어 몇 달 뒤엔 빈 주만 보인다), 예시에서 고친 것은 안 든다(늘 처음 상태). 단추는 예시 카드와 예시 중 관리 > 데이터 보관에. 받은 파일은 `example` 표시가 있어 끌어 놓기·[데이터 파일 열기]로 열어도 예시(저장 안 됨).
- **하지 않은 것**: 예시 파일을 병동 데이터 파일로 바꿔 쓰기(예시 표시를 떼는 단추) — [우리 병동 파일 만들기]가 빈 파일로 처음 설정을 묻는 편이 낫다(예시의 가짜 명부·당직이 섞인다).
- **끌어 놓기 주의**: `DataTransfer` 항목은 drop 처리기가 **첫 await 전에** 읽어야 한다 — 예시인지 보려고 파일 내용을 먼저 읽었더니 `getAsFileSystemHandle` 이 빈손이 됐다. 핸들 약속을 먼저 잡아 둔다.
- **검사**: 로직 39절(만들기 결정성 · 14병동 · 저장소 쓰기 감시 · 열기 길 넷 · 예시 파일 받기 · 끝내기 · 파일 만들기), e2e 1a(환영 단계 → 101병동 → 예시 카드 → 끝내기), 예시 파일 `--check`(CI).
