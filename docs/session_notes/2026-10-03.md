# 2026-10-03 (2) — 같은 폴더인데 처음에 '저장 연결 안 됨'

## 질문·제보
"저장파일 자동연동되는건 사용자명>문서 폴더에 있는 js 파일만 …?" → 문서 폴더 전용이 아니라 assign.html 옆 assign-data.js 만 켜자마자 뜬다고 답했다.
이어서 "같은 폴더에 있어도 처음에는 저장연결이 안되어있다고 떠. 읽기전용도 아니고."

## 재현 (헤드리스 크롬, file://, `--allow-file-access-from-files` 없이)
- 처음 켬: 노랑 '읽기 전용' + [저장 연결] — 여기까지는 의도대로.
- 기억된 핸들 없이 [저장 연결] → 파일 창에서 같은 파일을 고르면 연결은 됐는데(토스트 '저장 연결 완료') **알약이 빨강 '저장 연결 안 됨'**.
  자동으로 읽을 때(`openSidecar`) 적은 저장 문장이 `useHandle` 에서 안 지워져, 첫 저장 전까지 남았다. 제보 그대로("읽기 전용도 아니고").
- 함께 본 것: 읽기만 하는 중에 고치면 화면에만 있고 알약은 그대로 '읽기 전용', 창을 닫아도 아무것도 묻지 않아 고친 것이 사라진다.
- 새 파일을 문서 폴더에 assign-data.js 로 만들어도 "이 폴더에서는 다음부터 켜자마자 배정표가 뜹니다" — 이름만 보고 말했다.

## 고친 것
- `useHandle` 이 연결할 때 `saveState` 를 비운다.
- 읽기만 하는 중에 고치면 알약 빨강 '고친 것 저장 안 됨', 닫을 때 브라우저 확인. 알림은 '읽기 전용' 대신 "고친 내용이 아직 저장되지 않았습니다 — [저장 연결]".
- `newDataFile` 안내는 `fileLoc.verified` 로: HTML 옆이면 '다음부터는 켜면 바로', 아니면 '<HTML 이름> 파일이 있는 폴더로 옮겨 두세요'(+ 이름이 다르면 이름도).

## 확인하지 못한 것 (보수적으로 둔 것)
브라우저가 쓰기 허락을 다음에 켤 때까지 기억하는지(크롬의 '방문할 때마다 허용')는 file:// 에서 확인하지 못했다 —
기억하지 않는다고 보고 화면 문구를 그대로 두었다(켤 때마다 [허용] 한 번). 기억하는 브라우저면 `silentReattach` 가 이미 클릭 없이 잇는다.

## 검사
로직 35절(가짜 핸들·가짜 파일 창): 옛 assign.html 에서는 '저장 연결 안 됨'(off) 등 6건 실패, 지금은 514건 모두 통과. 원칙·호환 43건·실시간 수정 씨앗 1·2·3 통과.
e2e 의 '엑셀 받기' 1건은 이 컨테이너 크로미움이 blob 이름을 안 붙여서 — main 에서도 같고 CI(google-chrome)는 통과.

# 2026-10-03 (3) — 파일 창이 문서 폴더에서 열린다

## 요청
"js 파일 연동하는게 파일 탐색기 찾는 팝업이 그냥 유저명>문서 에서 시작하더라고 … 같은 폴더부터 띄워주면 좋을 것 같아."

## 한계
브라우저 파일 창(`showOpenFilePicker`·`showSaveFilePicker`)은 **경로를 받지 않는다** — `startIn` 은 이미 쥔 파일·폴더 핸들이나
바탕 화면·문서·다운로드 같은 정해진 이름뿐이다. 사이트 데이터를 지운 PC 는 핸들도, 브라우저가 기억한 폴더도 없으니 기본(문서)에서 열린다.

## 고친 것
- `pickWith`(→ `pickerOpts`): 기억한 데이터 파일의 폴더 > HTML 이 사용자 폴더의 바탕 화면·문서·다운로드 안이면 그 폴더(`wellKnownOf`, OneDrive '바탕 화면' 포함)
  > 브라우저 기본. 늘 `id:'assign-data'` — 한 번 고른 뒤에는 브라우저가 그 폴더를 이 창용으로 기억한다. 시작 폴더를 못 받으면 빼고 한 번 더.
  [저장 연결]·[처음 시작]·[데이터 파일 열기]·저장 위치 바꾸기가 같이 쓴다(백업 불러오기는 그대로 — 백업은 보통 다운로드에 있다).
- 윈도 경로(드라이브·공유 폴더)면 파일 창을 열기 전에 HTML 옆 파일 경로를 클립보드에 넣고 "파일 이름 칸에 Ctrl+V 를 누르고 Enter"를 알린다.
  윈도 파일 창은 파일 이름 칸에 전체 경로를 넣으면 그 파일로 간다 — **이 컨테이너에서는 윈도 파일 창을 띄울 수 없어 확인하지 못했다**.
- 함께 막은 것: 기억한 핸들이 이름만 같은 다른 폴더(예: 처음 만든 문서 폴더)의 파일이면 '허용' 한 번에 그쪽에 이어 써서 HTML 옆 파일이 옛 내용으로 남았다.
  `reattachHandle` 은 방금 자동으로 읽은 내용(rev·saved)과 같을 때만 잇고, 아니면 `__reattachOther` — 그 핸들은 시작 폴더로도 안 쓰고 다시 묻지 않는다.
  '허용' 창 뒤라 같은 클릭으로 파일 창이 안 열리면(SecurityError) 영어 오류 대신 "한 번 더 눌러 주세요".

## 검사
로직 36절(14건, 가짜 파일 창으로 옵션을 받아 본다): 시작 폴더 순서·경로 복사(드라이브·UNC·맥)·다른 폴더 핸들·몸짓 오류. 로직 528건 · 호환 43건 · 실시간 수정 통과,
e2e 는 '엑셀 받기' 1건(이 컨테이너 크로미움, main 에서도 같음)만 실패.
